### **🚨 CRITICAL LEARNING: PRODUCTION DATABASE HANDLING (2026-03-18 19:34)**
**Context:** PRDForge production database contains live user data
**Mistake Made:** Initially suggested recreating `prdforge_docs` table with INSERT statements
**Correction Received:** "The production database already has all sorts of live data do not try to recreate data. This is not the first installment of prdforge this is a dev server"

**Key Learnings:**
1. **Production vs Dev Distinction:** Must always verify if working with production data
2. **Data Preservation:** Never suggest recreating or overwriting production data
3. **Safe Diagnostics:** Use read-only checks only for production databases
4. **Migration Caution:** Apply migrations carefully, verify existing structures first

**Correct Approach for Production:**
1. **Check table existence** with `SELECT EXISTS` (read-only)
2. **Verify RLS policies** without modifying
3. **Check permissions** for app access
4. **Improve error handling** in code rather than modifying data
5. **Always assume data exists** in production unless proven otherwise

**Applied Correction:**
- Stopped all data modification suggestions
- Switched to read-only diagnostic approach
- Focused on code/configuration fixes instead of data fixes
- Acknowledged production environment constraints
